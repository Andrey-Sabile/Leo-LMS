# Admin Control Panel Feature Vertical Slice

Documentation for implementing the admin control panel that manages user provisioning, class creation, enrollment auditing, and compliance reporting.

---

## Feature Goals & Scope

- Provide admins with interfaces to create/update users (teachers, students, parents), assign roles, and manage credentials/invitations.
- Manage class creation, archive, and assignment of instructors from admin view.
- Oversee enrollments with auditing tools (search, filters, bulk actions) and history tracking.
- Generate compliance reports (enrollment counts, attendance summaries, grade distributions) with export options.
- Integrate with announcements for schoolwide communications and notifications for provisioning events.

Non-goals:
- SIS synchronization (future integration).
- Fine-grained authorization management beyond role assignment (document for security roadmap).
- Parent password management (handled via identity provider).

---

## Domain Design

### Aggregates & Entities

- **AdminProvisioningRequest (Aggregate Root)** – optional entity for tracking pending provisioning workflows.
  - Properties: `Id`, `RequesterId`, `TargetType` (User, Class, Enrollment), `Payload`, `Status`, `ProcessedOn`.
- **EnrollmentAuditLog** – records changes to class enrollments with `ActionType`, `PerformedBy`, `Timestamp`.
- Reuse existing domain entities (User, Classroom, ClassMembership) but expose admin-level services for management.

### Value Objects

- **ProvisioningPayload** storing structured data for new users/classes.
- **ComplianceReportDefinition** capturing parameters.

### Invariants & Business Rules

- Admin-only operations require elevated permissions; ensure actions logged with audit trail.
- Class creation via admin must still satisfy Class Management invariants (unique codes, primary instructor).
- Enrollment changes recorded in audit log with reason codes.
- Compliance reports must respect date ranges and include metadata (generated by, timestamp).

### Domain Events

- `UserProvisionedEvent`, `ClassCreatedByAdminEvent`, `EnrollmentAuditRecordedEvent`, `ComplianceReportGeneratedEvent`.

## Application Layer

Namespace `src/Application/Admin`.

### Commands

1. **ProvisionUserCommand : IRequest<Guid>** – create user with roles, send invitation email.
2. **UpdateUserRolesCommand : IRequest** – modify user roles/permissions.
3. **CreateClassByAdminCommand : IRequest<int>** – wrap class creation with admin context.
4. **ManageEnrollmentCommand : IRequest** – add/remove students, set status with audit reason.
5. **GenerateComplianceReportCommand : IRequest<Guid>** – triggers background job to produce report artifact.
6. **ProcessProvisioningRequestCommand : IRequest** – handle queued provisioning tasks.

### Queries

- **GetUsersAdminQuery** – search/filter users by role, status.
- **GetClassesAdminQuery** – list classes with instructor and enrollment counts.
- **GetEnrollmentAuditLogQuery** – historical changes per class/student.
- **GetComplianceReportsQuery** – list generated reports with download links.

### Validation & Mapping

- Validators for email uniqueness, role assignments, enrollment duplication.
- Map results to DTOs for Angular admin panel (user summary, audit entries, report metadata).

## Infrastructure

- DbSets for provisioning requests, audit logs, compliance report metadata.
- Integration with identity provider (e.g., ASP.NET Identity) for user creation.
- Background jobs for report generation (CSV/PDF) stored via artifact repository.
- Logging instrumentation for admin actions.

---

## Web API

- Endpoint group `Admin`.
- Endpoints: provision/update users, manage classes, manage enrollments, fetch audit logs, trigger/export compliance reports.
- Protected with admin policy; implement request logging + rate limiting.

---

## Angular Frontend

Feature folder `features/admin-control-panel`.

- **AdminDashboardComponent** – overview cards (user counts, pending requests).
- **UserManagementTableComponent** – DaisyUI `table` with filters, inline role toggles.
- **ClassManagementComponent** – list of classes with actions (create, archive, assign instructor).
- **EnrollmentAuditComponent** – timeline/table of changes.
- **ComplianceReportsComponent** – list of generated reports with download.
- Signals store handles search filters, pagination, selected entities.

UX Considerations:
- Use `badge` to indicate roles (Teacher, Admin, Parent).
- Provide multi-step modal for provisioning new user (collect details, assign classes).
- Show audit log with DaisyUI `timeline` or list group for readability.

## Testing Strategy

- **Domain.UnitTests**: provisioning payload validation, audit log invariants.
- **Application.UnitTests**: command handler coverage for user/class/enrollment actions, report generation triggers.
- **Infrastructure.IntegrationTests**: EF mapping for audit logs, identity provider integration mocks, report generation.
- **Web.AcceptanceTests**: API permission enforcement, provisioning flows.
- **Angular Tests**: component tests for user management table, modals; store tests for filter/pagination.
